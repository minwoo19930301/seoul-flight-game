# 서울 전역 공개자료 통합 — 범위와 한계

2026-09-07. 사용자는 VWorld 계정·키 없이 진행하도록 선택했습니다. 신규 앱은 서울 25개 구의 공개 건물 윤곽과 전역 지형·수면을 실제 런타임에 연결했습니다. **실사 외관이나 실측 정확도·모든 실제 건물의 완전성은 확보하지 못했습니다.** 이 문서는 코드/자료 상태이며 배포 또는 브라우저 검증 보고가 아닙니다.

## 정확히 연결한 범위

- [Overture 2026-08-19.0](https://docs.overturemaps.org/release/latest/), 익명 공개 STAC/GeoParquet에서 가져온 건물 365,456동과 부분 형상 1,684개.
- 서울 행정경계 GERS `2d4b9f73-5037-4823-92b9-2084675e7d8d`, OSM [relation 2297418](https://www.openstreetmap.org/relation/2297418) revision149. 원본 경계의 갱신은 2026-07-22, OSM planet 시점은 2026-07-23입니다. 원본 객체 갱신은 측량/촬영 날짜가 아닙니다.
- 25개 구 경계 합집합과 서울 경계의 대칭 차이는 0입니다. 건물은 경계와 교차하면 원래 윤곽 전체를 보존하며 하나의 구에만 배정합니다. 서울 외부만 있는 건물은 제외합니다. 경계 교차 건물51개는 임의 절단하지 않았습니다.
- W126.7644328 / E127.1837886 / S37.4285424 / N37.7014794, 기준 위도 보정 local Mercator 가로37,003.43m·세로30,383.27m. 이는 행정구역을 감싼 사각형이며 서울 면적이나 건물 포괄률이 아닙니다.
- 지형과 수면은 같은 사각형 전체를 제공하므로 경계 밖 인접 지역의 땅/물도 보입니다. 인접 지역 건물은 이번 선택 범위가 아닙니다.
- [소스 manifest](../assets/full-seoul/source/manifest.json), [원본 검증](../assets/full-seoul/source/validation.json), [경계](../assets/full-seoul/source/districts.geojson).

## 높이·형상·중복 정책

|원본 유형|수량|높이값 있음|높이 미제공|
|---|---:|---:|---:|
|건물|365,456|26,626 (7.3%)|338,830|
|부분 형상|1,684|504|1,180|

건물164,237동은 OSM,201,219동은 [Qian Shi 외 동아시아 공개 건물 자료](https://doi.org/10.5281/zenodo.8174931)에서 온 Overture 형상입니다. 후자는 항공영상에서 추출한 roofprint/footprint 성격으로, 최신 대장·정확한 지상 외벽을 보장하지 않습니다. 높이 필드의 존재도 측량 방식·준공 높이를 보증하지 않습니다.

원본 gzip NDJSON에는 ID, Polygon/MultiPolygon, 구멍, `building_id`, 출처, 원래 높이와 null을 그대로 보존합니다. 런타임 렌더 정책은 별도입니다.

1. 양의 원본 높이는 그대로 사용하며 임의 최대값으로 자르지 않습니다. 부분 형상의554.5m도 보존합니다.
2. 높이 결측이면 층수×3.1m, 부분 형상에 본체 높이가 있으면 해당 값, 둘 다 없으면8m를 **추정**으로 표시합니다. 층수 추정도 실측이 아닙니다. 청회색=높이값 있음, 회갈색=추정이며 UI에 원본 통계를 표시합니다.
3. 본체 외곽에서 연결된 부분 형상의 실제 합집합을 차감합니다. 완전히 덮인 본체328개는 중복 지붕을 만들지 않고,169개 본체의 남은 구역은 보존합니다. 부분은 본체와 동일한 지형 기준점을 사용하며 각자의 min_height/층수 정책을 유지합니다.
4. 별도 제작한 랜드마크 본체5개와 연결된 부분61개, 총66개만 제외합니다. 주변 건물군을 원형으로 비우지 않습니다. [정확한 제외 ID와 이유](../assets/full-seoul/city-manifest.json).
5. 최종 렌더 형상366,746개, polygon367,244개, 구멍253개. 원본 자체의 중정220개와 달리 부모 차감에서 생긴 구멍도 포함한 렌더 수량입니다.
6. 원본 double 좌표를 tile-local Float32 GPU 버퍼로 변환하면서 극소 삼각형19개가 퇴화해 제거됐고26개는 출력 좌표에 맞춰 방향을 재계산했습니다. 원본 데이터는 변경하지 않았으며 모든 출력 삼각형 법선과 방향을 CPU 검사했습니다.

지붕은 구멍 있는 평지붕 삼각화이며 실제 지붕 경사/곡면이 아닙니다. 창·멀리언·벽 색상은 직접 제작한 반복 무늬와 중립색입니다. 실제 사진을 텍스처로 복제하거나 가짜 정밀 외관이라고 설명하지 않습니다. 경복궁 모델은 근정전 중심 참고 모델입니다.

## 지형·수면과 충돌

[AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) Terrarium z12 실제30타일을 복호화했습니다. 원본은 과거 SRTM/GMTED 혼합자료이며 현재 도시의 지반 측량이 아닙니다. 약30m 원본에서44.96×44.95m 간격의824×677표본(557,848점)을 보존했습니다. 엄밀한 단일 수직기준 확인을 주장하지 않습니다.

- 원본 SHA256: `80d5fd912de0942f2899b7f44aa08a772fb042d015b390003cb1a57c24a08460`.
- 원시 최솟값−137.370m, 최댓값809.309m. 음수139점 중94점은 서울 안이며, −20m 미만10점 중9점도 안에 있습니다. 특히126.8067251/37.5982363의−137.37m는 인접 표본과 큰 차이가 있어 artifact가 강하게 의심됩니다. [원본 품질 감사](../assets/full-seoul/terrain/terrain-quality-audit.json).
- **원본 값을 0으로 바꾸거나 구역을 평탄화하지 않았습니다.** 건물은 원본 SW–NE 삼각면 고도를 바닥으로 사용합니다.
- 표시 지형은 desktop421×346(289,800삼각형), mobile281×231(128,800삼각형) LOD로 낮춰, 원시 전면1,112,696삼각형을 항상 GPU에 보내지 않습니다. 이 LOD는 명시적인 시각 근사이며 급경사에서는 건물/지면의 교차나 표면 오차가 남을 수 있습니다.
- 항공 충돌 하한만 `max(원본 삼각면 고도, 표시 LOD 고도, 0m) + 18m`로 정합니다. 음수 artifact로 급강하하거나 LOD 지면을 관통하지 않도록 한 **게임 안전 정책**이며 교정된 측량값이 아닙니다. 천장1600m, 자료 사각형 안쪽50m에서 복귀합니다. 일반 건물 충돌은 하지 않습니다.
- 수면은 새 OSM bbox 질의의660개 원본에서 합친548개 polygon/121개 구멍이며 섬을 채우지 않습니다. 자체 교차 원본3개는 임의 수선 없이 제외했습니다. [수면 provenance](../assets/full-seoul/water/provenance.json).
- 수면은 표시 지형 위0.3m에 드레이핑하므로 수평 수위·현행 홍수위가 아닙니다. CPU 전체 수면 삼각화243,408개를 검사했습니다.

## 시작 비용·상세도·누락 표시

초기 핵심 자료는 **2,422,645bytes**: 지도 메타·타일 manifest·압축 DEM·수면·구 경계입니다. Three.js/worker코드·약2.4MB 랜드마크와 첫 주변 청크는 별도입니다. 이전14MB scene JSON, 래스터,204개 중심 구역 GLB는 새로운 앱에서 불러오지 않습니다.

657개1km청크의 전체 압축 합은61,515,198bytes, 가장 큰 청크533,377bytes입니다. 전체를 한 번에 요청하지 않습니다. 단일 module Worker가 gzip/JSON/중정 삼각화를 처리하며 네트워크/작업 요청은 최대3개입니다. 떠난 구역의 geometry를 회수하고 실패 구역은 HUD에 표시·R로 재시도합니다.

- 근거리: 낮고 작은 건물324,653개. desktop1.9km / mobile1.1km 청크 반경.
- 원거리: 표시 높이24m 이상 또는 면적500m² 이상42,093개. desktop4.3km / mobile2.8km 반경.
- 두 분류는 서로 겹치지 않습니다. 둘 다 실제 다각형이며 AABB 대체물을 만들지 않습니다. 분류별 거리 디더 페이드로 작은 건물의 갑작스러운 출현을 줄입니다. 멀리 사라진 건물은 원본 누락이 아니라 공개된 LOD 정책입니다.
- 고도색 지형과 실제 물 폴리곤을 지면/미니맵으로 사용합니다. 과거 도심 도로 중심선은 그 원래 범위에만 남겨두었으며 **서울 전역 도로·차로·교량·식생·실사 외관은 확보하지 않았습니다.**

CPU 데이터 경로에 이어 로컬 실제 WebGL 렌더와 25구 이동·주변 그룹 로딩까지 [별도 브라우저 기록](browser-verification-20260907.md)으로 확인했습니다. 모든 거리 전환의 시각 품질, 실제 기기 프레임률·장시간 GPU 메모리는 미검증입니다. 높은 지점이나 외곽에서 도시가 실사처럼 이어진다고 주장하지 않습니다.

## 재현 및 권리

[건물/경계 ODbL 및 원본별 attribution](../assets/full-seoul/source/ATTRIBUTION.md), [Overture 공식 attribution](https://docs.overturemaps.org/attribution/), [OSM copyright](https://www.openstreetmap.org/copyright)를 유지합니다. 동아시아 원본은 CC BY4.0, DEM은 포함 manifest의 USGS/Mapzen attribution을 따릅니다. 생성된 중립 창 무늬는 기존 저장소의 오리지널 이미지입니다. 원본 항공사진·유료 3D·인증키·사용자 메타데이터는 포함하지 않았습니다.

Python3.12 + Shapely2.1.2에서 오프라인 재생성합니다. 공개 원본은 모두 저장소 안에 있습니다.

보존된 공개 원본만으로 별도 폴더에 다시 생성해657개 청크와5개 핵심 메타/압축 파일, 총662개 파일의 SHA256이 모두 동일한 것을 확인했습니다. 검증용 임시 경로는 공개 metadata에 기록하지 않았습니다.

```sh
python3 scripts/prepare-full-seoul.py \
  --buildings assets/full-seoul/source \
  --terrain assets/full-seoul/terrain \
  --water assets/full-seoul/water \
  --base-map assets/full-seoul/scene.json
npm test
npm run test:full-city
npm run build
```

원본 CLI 상태·가상환경·캐시·원본 OSM contributor 사용자 메타데이터는 allowlist에서 제외했습니다. 일부 원본 metadata의 상대 sibling 경로는 취득 당시의 자료 구성을 기록한 것이며, 공개 사본은 이 문서의 `assets/full-seoul/source|terrain|water`에 있습니다.

[VWorld 공식3D](https://www.data.go.kr/data/3073144/openapi.do), [서울 S-Map](https://english.seoul.go.kr/policy/smart-city/spatial-data/) 같은 실사 공급은 이번 키 없는 범위에 연결하지 않았습니다. 공개 뷰어를 무단 추출하지 않으며 가입·키 제출을 요구하지 않습니다.
